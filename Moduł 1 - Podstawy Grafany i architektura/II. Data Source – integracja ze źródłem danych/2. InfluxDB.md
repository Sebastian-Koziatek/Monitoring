# InfluxDB

## Wprowadzenie do InfluxDB
![InfluxDB](/grafiki/m1-014-influxdb.png)

**InfluxDB** to otwartoźródłowa baza danych szeregów czasowych (time-series database) zaprojektowana specjalnie do przechowywania i analizowania danych z dużą liczbą pomiarów w czasie. Jest idealnym rozwiązaniem do monitorowania infrastruktury IT, aplikacji IoT, metryk biznesowych oraz analizy wydajności.

### Kluczowe cechy InfluxDB:

- **Wysoka wydajność zapisu** - posiada wysoką przepustowość dla operacji zapisu danych czasowych
- **Kompresja danych** - automatyczna kompresja danych czasowych pozwala na efektywne wykorzystanie przestrzeni dyskowej
- **Język zapytań Flux** - nowoczesny język do zapytań i przetwarzania danych (w InfluxDB 2.x)
- **Retention policies** - automatyczne usuwanie starych danych według zdefiniowanych zasad
- **Continuous queries** - możliwość agregacji danych w czasie rzeczywistym
- **Natywna integracja** - łatwa integracja z narzędziami takimi jak Grafana, Telegraf, czy Kapacitor

### Architektura InfluxDB 2.x:

InfluxDB 2.x wprowadza nową, zunifikowaną platformę, która łączy:
- **Bazę danych** - przechowywanie danych szeregów czasowych
- **Interfejs UI** - graficzny interfejs do zarządzania danymi
- **Telegraf** - agent do zbierania metryk
- **Tasks** - zaplanowane zadania przetwarzania danych
- **Alerts** - system powiadomień i alertów

### Różnice między InfluxDB 1.x a 2.x:

| Cecha | InfluxDB 1.x | InfluxDB 2.x |
|-------|--------------|--------------|
| Język zapytań | InfluxQL | Flux (+ kompatybilność z InfluxQL) |
| Autoryzacja | Użytkownik/hasło | Token-based authentication |
| Organizacja danych | Database + Retention Policy | Organization > Bucket |
| UI | Chronograf (osobny) | Wbudowany UI |
| API | REST API | Zunifikowane API v2 |

## Telegraf - Agent zbierający metryki

![Telegraf](/grafiki/m1-021-telegraf.png)

**Telegraf** to lekki agent serwerowy do zbierania i raportowania metryk. Jest napisany w języku Go i charakteryzuje się minimalnym zużyciem zasobów systemowych.

### Kluczowe cechy Telegraf:

- **Architektura plugin-based** - ponad 300 wtyczek wejściowych i wyjściowych
- **Małe zużycie zasobów** - niewielkie obciążenie CPU i pamięci
- **Łatwa konfiguracja** - prosty format konfiguracji TOML
- **Wsparcie dla wielu protokołów** - StatsD, Graphite, collectd, OpenTelemetry
- **Przetwarzanie danych** - możliwość agregacji i transformacji metryk przed wysłaniem

## Instalacja i konfiguracja InfluxDB 2.x

### Wymagania systemowe:

- **System operacyjny**: Ubuntu 20.04+, Debian 10+, RHEL/CentOS 7+
- **Pamięć RAM**: minimum 2 GB (zalecane 4 GB+)
- **Przestrzeń dyskowa**: minimum 5 GB (zależnie od retencji danych)
- **CPU**: 2+ rdzenie (zalecane)

### Instalacja InfluxDB na Ubuntu 24.04

#### Metoda 1: Za pomocą skryptu instalacyjnego

Poniżej znajduje się kompletny skrypt automatyzujący instalację InfluxDB 2.x i Telegraf:

```bash
#!/bin/bash

################################################################################
# Skrypt instalacji InfluxDB 2.x i Telegraf dla Ubuntu 24.04
################################################################################

set -e  # Zatrzymaj skrypt przy błędzie
set -u  # Zatrzymaj przy użyciu niezdefiniowanych zmiennych

# Kolory dla outputu
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# Funkcje pomocnicze
log_info() {
    echo -e "${GREEN}[INFO]${NC} $1"
}

log_warn() {
    echo -e "${YELLOW}[WARN]${NC} $1"
}

log_error() {
    echo -e "${RED}[ERROR]${NC} $1"
}

check_root() {
    if [ "$EUID" -ne 0 ]; then 
        log_error "Ten skrypt musi być uruchomiony jako root (sudo)"
        exit 1
    fi
}

install_dependencies() {
    log_info "Instalowanie zależności..."
    apt-get update -qq
    apt-get install -y wget gnupg2 curl apt-transport-https ca-certificates
    log_info "Zależności zainstalowane"
}

install_influxdb() {
    log_info "=== Instalacja InfluxDB 2.x ==="
    
    # Dodaj klucz GPG InfluxData
    curl -fsSL https://repos.influxdata.com/influxdata-archive.key | \
        gpg --dearmor --yes -o /etc/apt/trusted.gpg.d/influxdata-archive.gpg
    
    chmod 644 /etc/apt/trusted.gpg.d/influxdata-archive.gpg
    
    # Dodaj repozytorium
    echo "deb [signed-by=/etc/apt/trusted.gpg.d/influxdata-archive.gpg] https://repos.influxdata.com/debian stable main" | \
        tee /etc/apt/sources.list.d/influxdata.list
    
    # Instaluj
    apt-get update -qq
    apt-get install -y influxdb2 influxdb2-cli
    
    # Uruchom
    systemctl enable influxdb
    systemctl start influxdb
    
    log_info "✓ InfluxDB uruchomiony na http://localhost:8086"
}

install_telegraf() {
    log_info "=== Instalacja Telegraf ==="
    
    apt-get install -y telegraf
    systemctl enable telegraf
    
    log_info "✓ Telegraf zainstalowany"
}

main() {
    check_root
    install_dependencies
    install_influxdb
    install_telegraf
    
    log_info "Instalacja zakończona!"
    echo "Następny krok: skonfiguruj InfluxDB na http://localhost:8086"
}

main
```

Zapisz skrypt jako `install_influxdb.sh`, nadaj uprawnienia i uruchom:

```bash
chmod +x install_influxdb.sh
sudo ./install_influxdb.sh
```

### Konfiguracja początkowa InfluxDB

#### Metoda 1: Przez interfejs webowy (zalecana)

1. Otwórz przeglądarkę i przejdź do: `http://localhost:8086`
2. Wypełnij formularz początkowej konfiguracji:
   - **Username**: admin (lub inna nazwa użytkownika)
   - **Password**: silne hasło (minimum 8 znaków)
   - **Organization Name**: myorg (lub nazwa Twojej organizacji)
   - **Bucket Name**: telegraf (nazwa domyślnego bucketa)
   - **Retention Period**: 168h (7 dni) lub inna wartość
3. Kliknij **Continue**
4. Skopiuj i zapisz wygenerowany **API Token** - będzie potrzebny do konfiguracji Telegraf

#### Metoda 2: Przez wiersz poleceń

```bash
influx setup \
    --username admin \
    --password 'TwojeHaslo123!' \
    --org myorg \
    --bucket telegraf \
    --retention 168h \
    --force
```

**Wyjaśnienie parametrów:**
- `--username` - nazwa użytkownika administratora
- `--password` - hasło (użyj silnego hasła!)
- `--org` - nazwa organizacji
- `--bucket` - nazwa domyślnego bucketa do przechowywania danych
- `--retention` - okres retencji danych (168h = 7 dni, 0 = bez limitu)
- `--force` - wymusza setup nawet jeśli już był wykonany

### Generowanie dodatkowych tokenów

```bash
# Token z pełnymi uprawnieniami
influx auth create \
    --org myorg \
    --all-access \
    --description "Admin token for Telegraf"

# Token tylko do zapisu do konkretnego bucketa
influx auth create \
    --org myorg \
    --write-bucket telegraf \
    --description "Write-only token for Telegraf"

# Token tylko do odczytu
influx auth create \
    --org myorg \
    --read-bucket telegraf \
    --description "Read-only token for Grafana"
```

### Lista istniejących tokenów

```bash
influx auth list --org myorg
```

### Konfiguracja Telegraf dla InfluxDB 2.x

1. **Backup oryginalnej konfiguracji:**
   ```bash
   sudo cp /etc/telegraf/telegraf.conf \
       /etc/telegraf/telegraf.conf.backup
   ```

2. **Utwórz nową konfigurację:**
   ```bash
   sudo nano /etc/telegraf/telegraf.conf
   ```

3. **Podstawowa konfiguracja dla InfluxDB 2.x:**

```toml
# Global Agent Configuration
[agent]
  interval = "10s"
  round_interval = true
  metric_batch_size = 1000
  metric_buffer_limit = 10000
  collection_jitter = "0s"
  flush_interval = "10s"
  flush_jitter = "0s"
  precision = "0s"
  hostname = ""
  omit_hostname = false

###############################################################################
#                            OUTPUT PLUGINS                                   #
###############################################################################

# Konfiguracja output do InfluxDB 2.x
[[outputs.influxdb_v2]]
  ## URL serwera InfluxDB
  urls = ["http://localhost:8086"]
  
  ## Token autoryzacyjny (zastąp własnym tokenem)
  token = "WKLEJ_TUTAJ_SWOJ_TOKEN"
  
  ## Nazwa organizacji
  organization = "myorg"
  
  ## Nazwa bucketa
  bucket = "telegraf"
  
  ## Timeout dla żądań HTTP
  timeout = "5s"
  
  ## Opcjonalne: konfiguracja TLS (dla połączeń HTTPS)
  # tls_ca = "/etc/telegraf/ca.pem"
  # tls_cert = "/etc/telegraf/cert.pem"
  # tls_key = "/etc/telegraf/key.pem"
  # insecure_skip_verify = false

###############################################################################
#                            INPUT PLUGINS                                    #
###############################################################################

# Metryki CPU
[[inputs.cpu]]
  percpu = true
  totalcpu = true
  collect_cpu_time = false
  report_active = false
  core_tags = false

# Metryki dysku
[[inputs.disk]]
  ## Ignoruj systemy plików
  ignore_fs = ["tmpfs", "devtmpfs", "devfs", "iso9660", "overlay", "aufs", "squashfs"]

# Metryki I/O dysku
[[inputs.diskio]]

# Metryki pamięci
[[inputs.mem]]

# Metryki procesów
[[inputs.processes]]

# Metryki swap
[[inputs.swap]]

# Metryki systemu (load, uptime, number of users)
[[inputs.system]]

# Metryki interfejsów sieciowych
[[inputs.net]]
  interfaces = ["eth*", "enp*", "ens*"]

# Statystyki netstat
[[inputs.netstat]]

# Informacje o kernelu
[[inputs.kernel]]

# Statystyki Linux kernel
[[inputs.kernel_vmstat]]

# Statystyki procesów Linux
[[inputs.linux_sysctl_fs]]
```

4. **Testuj konfigurację:**

   ```bash
   telegraf --test --config /etc/telegraf/telegraf.conf --once
   ```

5. **Uruchom Telegraf:**
   ```bash
   sudo systemctl start telegraf
   sudo systemctl status telegraf
   ```

6. **Sprawdź logi:**

### Organizacja konfiguracji Telegraf

Zamiast jednego dużego pliku, możesz podzielić konfigurację na mniejsze pliki:

```bash
# Struktura katalogów
/etc/telegraf/
├── telegraf.conf            # Główna konfiguracja + outputs
└── telegraf.d/              # Dodatkowe pliki konfiguracyjne
    ├── cpu.conf
    ├── disk.conf
    ├── docker.conf
    ├── nginx.conf
    └── mysql.conf
```

W głównym pliku `telegraf.conf` dodaj:
```toml
[agent]
  # ... konfiguracja agenta ...

[[outputs.influxdb_v2]]
  # ... konfiguracja outputu ...

# Włącz automatyczne ładowanie plików z katalogu telegraf.d
```

Telegraf automatycznie ładuje wszystkie pliki `.conf` z katalogu `/etc/telegraf/telegraf.d/`.

## Konfiguracja Grafany z InfluxDB

### Dodawanie źródła danych InfluxDB 2.x do Grafany

1. **Zaloguj się do Grafany** i przejdź do **Configuration** → **Data Sources** (ikona koła zębatego w menu bocznym)

2. **Kliknij "Add data source"**

3. **Wybierz "InfluxDB"** z listy dostępnych źródeł danych

4. **Skonfiguruj połączenie:**

   **Query Language**: Wybierz **Flux** (zalecane dla InfluxDB 2.x)
   
   **HTTP:**
   - **URL**: `http://localhost:8086` (lub adres IP serwera InfluxDB)
   - **Access**: Server (default) - Grafana łączy się z InfluxDB ze swojego serwera
   
   **Auth:**
   - Pozostaw wszystkie opcje wyłączone (autoryzacja przez token)
   
   **InfluxDB Details:**
   - **Organization**: `myorg` (nazwa Twojej organizacji w InfluxDB)
   - **Token**: Wklej token wygenerowany podczas setup InfluxDB
   - **Default Bucket**: `telegraf` (opcjonalnie - bucket domyślny)
   - **Min time interval**: `10s` (zgodnie z intervalem w Telegraf)

5. **Kliknij "Save & Test"** - powinieneś zobaczyć komunikat: *"datasource is working. X buckets found"*

### Tworzenie pierwszego dashboardu

1. **Utwórz nowy dashboard**: **Dashboards** → **New Dashboard** → **Add a new panel**

2. **Wybierz źródło danych**: InfluxDB (Twoje skonfigurowane źródło)

3. **Napisz zapytanie Flux** (przykłady poniżej)

4. **Skonfiguruj wizualizację** i **zapisz panel**

## Przykładowe zapytania Flux

### 1. Wykorzystanie CPU (wszystkie rdzenie)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "cpu")
  |> filter(fn: (r) => r["_field"] == "usage_idle")
  |> filter(fn: (r) => r["cpu"] == "cpu-total")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> map(fn: (r) => ({ r with _value: 100.0 - r._value }))
  |> yield(name: "cpu_usage")
```

**Wyjaśnienie:**
- `from(bucket: "telegraf")` - wybierz bucket
- `range()` - zakres czasowy z zmiennych Grafany
- `filter()` - filtruj metrykę CPU i pole usage_idle
- `aggregateWindow()` - agreguj dane według okna czasowego Grafany
- `map()` - przekształć idle na usage (100% - idle)

### 2. Wykorzystanie pamięci RAM (procenty)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "mem")
  |> filter(fn: (r) => r["_field"] == "used_percent")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "memory_usage")
```

### 3. Wykorzystanie dysku (procenty dla każdej partycji)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "disk")
  |> filter(fn: (r) => r["_field"] == "used_percent")
  |> filter(fn: (r) => r["path"] == "/" or r["path"] == "/home" or r["path"] == "/var")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "disk_usage")
```

### 4. Transfer sieciowy (bytes in/out)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "net")
  |> filter(fn: (r) => r["_field"] == "bytes_sent" or r["_field"] == "bytes_recv")
  |> filter(fn: (r) => r["interface"] =~ /^(eth|enp|ens)/)
  |> derivative(unit: 1s, nonNegative: true)
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "network_traffic")
```

**Wyjaśnienie:**
- `derivative(unit: 1s)` - oblicza różnicę wartości na sekundę (rate)
- `nonNegative: true` - ignoruje wartości ujemne (resetowanie licznika)

### 5. Load average systemu

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "system")
  |> filter(fn: (r) => r["_field"] == "load1" or r["_field"] == "load5" or r["_field"] == "load15")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "system_load")
```

### 6. Liczba procesów

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "processes")
  |> filter(fn: (r) => r["_field"] == "total" or r["_field"] == "running" or r["_field"] == "sleeping")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "processes")
```

### 7. Temperatura CPU (jeśli dostępna)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "temp")
  |> filter(fn: (r) => r["_field"] == "temp")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "temperature")
```

### 8. Top 5 procesów według użycia CPU

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "procstat")
  |> filter(fn: (r) => r["_field"] == "cpu_usage")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> top(n: 5, columns: ["_value"])
  |> yield(name: "top_processes")
```

### 9. IOPS dysku (operacje odczytu/zapisu na sekundę)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "diskio")
  |> filter(fn: (r) => r["_field"] == "reads" or r["_field"] == "writes")
  |> derivative(unit: 1s, nonNegative: true)
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
  |> yield(name: "disk_iops")
```

### 10. Uptime systemu (w godzinach)

```flux
from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "system")
  |> filter(fn: (r) => r["_field"] == "uptime")
  |> map(fn: (r) => ({ r with _value: float(v: r._value) / 3600.0 }))
  |> aggregateWindow(every: v.windowPeriod, fn: last, createEmpty: false)
  |> yield(name: "uptime_hours")
```

## Zaawansowane funkcje Flux

### Agregacje i transformacje

```flux
// Średnia z ostatnich 5 minut
from(bucket: "telegraf")
  |> range(start: -5m)
  |> filter(fn: (r) => r["_measurement"] == "cpu")
  |> filter(fn: (r) => r["_field"] == "usage_idle")
  |> mean()

// Suma transferu sieciowego
from(bucket: "telegraf")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "net")
  |> filter(fn: (r) => r["_field"] == "bytes_sent")
  |> sum()

// Maksymalna wartość
from(bucket: "telegraf")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "mem")
  |> filter(fn: (r) => r["_field"] == "used_percent")
  |> max()

// Minimalna wartość
from(bucket: "telegraf")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "cpu")
  |> filter(fn: (r) => r["_field"] == "usage_user")
  |> min()
```

### Join - łączenie dwóch zapytań

```flux
// Porównaj użycie CPU i pamięci
cpu = from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "cpu" and r["_field"] == "usage_user")
  |> aggregateWindow(every: v.windowPeriod, fn: mean)

mem = from(bucket: "telegraf")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "mem" and r["_field"] == "used_percent")
  |> aggregateWindow(every: v.windowPeriod, fn: mean)

join(tables: {cpu: cpu, mem: mem}, on: ["_time", "host"])
```

## Zadania (Tasks) w InfluxDB

Tasks pozwalają na automatyczne przetwarzanie danych, np. downsampling (agregację starszych danych).

### Przykład: Downsampling danych CPU do średnich godzinowych

```flux
option task = {
  name: "downsample-cpu-hourly",
  every: 1h,
  offset: 5m
}

from(bucket: "telegraf")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "cpu")
  |> filter(fn: (r) => r["_field"] == "usage_idle" or r["_field"] == "usage_user")
  |> aggregateWindow(every: 1h, fn: mean, createEmpty: false)
  |> to(bucket: "telegraf_hourly", org: "myorg")
```

## Alerting w InfluxDB

InfluxDB 2.x posiada wbudowany system alertów, ale Grafana oferuje bardziej zaawansowane możliwości:

### Przykład: Alert w Grafanie dla wysokiego CPU

Od Grafana v8+ alerty są zarządzane centralnie w **Grafana Alerting**, niezależnie od paneli. Szczegółowy opis konfiguracji alertów znajduje się w dziale VI.

1. Przejdź do **Alerting > Alert rules** i kliknij **New alert rule**.
2. W sekcji **Define query** wybierz InfluxDB jako źródło danych i wpisz zapytanie Flux zwracające metrykę CPU.
3. W sekcji **Set alert conditions** ustaw próg, np. `IS ABOVE 80`.
4. Przypisz alert do **Contact point** (Email, Slack, PagerDuty itp.).
5. Zapisz regułę.

## Najlepsze praktyki

### 1. Optymalizacja wydajności

- **Używaj odpowiednich retention policies** - nie przechowuj szczegółowych danych dłużej niż to konieczne
- **Downsampling** - agreguj stare dane do mniejszej granularności (np. z 10s do 1h)
- **Indeksowanie** - InfluxDB automatycznie indeksuje tagi, nie pola
- **Ograniczaj cardinalność** - nie używaj wartości o wysokiej zmienności jako tagów
- **Batch writes** - Telegraf domyślnie wysyła dane w batch'ach, nie zmieniaj tej konfiguracji bez potrzeby

### 2. Bezpieczeństwo

- **Używaj tokenów z ograniczonymi uprawnieniami** - token dla Telegraf powinien mieć tylko prawo zapisu do konkretnego bucketa
- **Włącz TLS/HTTPS** - szczególnie dla zdalnego dostępu
- **Regularnie rotuj tokeny** - zmniejsz ryzyko kompromitacji
- **Firewall** - ogranicz dostęp do portu 8086 tylko dla zaufanych hostów

### 3. Monitorowanie InfluxDB

Monitoruj sam InfluxDB używając jego wbudowanych metryk:

```flux
from(bucket: "_monitoring")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "http_request")
  |> filter(fn: (r) => r["_field"] == "req_duration_seconds")
  |> aggregateWindow(every: v.windowPeriod, fn: mean)
```

### 4. Backup i restore

```bash
# Backup całej organizacji
influx backup /path/to/backup --org myorg

# Backup konkretnego bucketa
influx backup /path/to/backup --bucket telegraf --org myorg

# Restore
influx restore /path/to/backup --org myorg
```

### 5. Struktura danych

**Dobrze:**
- Użyj tagów dla wartości kategorycznych (hostname, region, environment)
- Użyj pól dla wartości numerycznych (cpu_usage, mem_usage)
- Zachowaj niską cardinalność tagów

**Źle:**
- Nie używaj timestamp jako tag
- Nie używaj UUID jako tag
- Nie twórz zbyt wielu tagów (idealne: 4-6 tagów na measurement)

### 6. Konfiguracja Telegraf

```toml
# Optymalna konfiguracja agenta
[agent]
  interval = "10s"              # Częstotliwość zbierania metryk
  round_interval = true         # Zaokrąglaj czas zbierania
  metric_batch_size = 1000      # Liczba metryk w jednym batch
  metric_buffer_limit = 10000   # Maksymalny bufor metryk
  flush_interval = "10s"        # Jak często wysyłać dane
  flush_jitter = "5s"           # Losowe opóźnienie flush (redukuje spike)
```

## Podsumowanie

InfluxDB i Telegraf tworzą potężny stack do zbierania, przechowywania i analizowania danych szeregów czasowych. W połączeniu z Grafaną otrzymujemy kompletne rozwiązanie do monitorowania infrastruktury IT:

- **Telegraf** zbiera metryki z różnych źródeł
- **InfluxDB** przechowuje dane w sposób zoptymalizowany pod kątem szeregów czasowych
- **Grafana** wizualizuje dane i zarządza alertami

Przy odpowiedniej konfiguracji retention policies i downsamplingu, system może efektywnie obsługiwać monitoring nawet bardzo dużych infrastruktur przy rozsądnym zużyciu zasobów.

**Kluczowe punkty do zapamiętania:**
- InfluxDB 2.x używa tokenów zamiast user/password
- Flux jest bardziej elastyczny niż InfluxQL
- Telegraf jest lekki i bardzo konfigurowalny
- Retencja danych powinna być dostosowana do potrzeb
- Monitoruj sam InfluxDB aby uniknąć problemów z wydajnością
