Grafana oferuje siedem typów zmiennych. Każdy typ ma inne zastosowanie — wybór właściwego decyduje o tym, jak użytkownik może filtrować i personalizować dashboard.

---

## Przegląd typów

| Typ | Opis | Typowe zastosowanie |
|-----|------|---------------------|
| Query | Wartości pobierane z zapytania do źródła danych | Lista hostów, serwisów, środowisk |
| Custom | Ręcznie zdefiniowana lista wartości | Środowiska (`dev`, `prod`, `test`) |
| Interval | Predefiniowane interwały czasowe | Granularność wykresu (1m, 5m, 1h) |
| Constant | Stała wartość niewidoczna dla użytkownika | Bazowy URL API, prefiks metryki |
| Data source | Przełącznik między instancjami źródła danych | Wybór środowiska Prometheus |
| Ad hoc filters | Dynamiczne filtry klucz=wartość do wszystkich zapytań | Szybkie filtrowanie po tagach |
| Text box | Dowolny tekst wpisany przez użytkownika | Filtrowanie po fragmencie nazwy |

---

## Query

Najczęściej używany typ. Grafana wysyła zapytanie do wybranego źródła danych i jako wartości zmiennej używa zwróconych wyników.

**Konfiguracja:**
1. **Type** → `Query`
2. **Data source** → wybierz źródło (np. Prometheus, Zabbix)
3. **Query** → zapytanie zwracające listę wartości

**Przykłady zapytań:**

Prometheus (pobierz unikalne wartości etykiety `instance`):
```
label_values(up, instance)
```

Prometheus (etykiety tylko z określonej metryki):
```
label_values(node_cpu_seconds_total{job="node_exporter"}, instance)
```

Zabbix (lista hostów z grupy):
```
{zbx_group_hosts: "Linux servers"}
```

**Opcje:**
- **Refresh** — kiedy lista wartości ma być odświeżana: `Never`, `On dashboard load`, `On time range change`
- **Regex** — filtrowanie wyników wyrażeniem regularnym, np. `/^prod-.*/` wyświetli tylko hosty zaczynające się od `prod-`
- **Sort** — kolejność wartości na liście

## Custom

Stała lista wartości definiowana ręcznie. Przydatna, gdy wartości nie pochodzą z danych (np. nazwy środowisk).

**Konfiguracja:**
1. **Type** → `Custom`
2. **Values** → wartości oddzielone przecinkami

**Przykład:**
```
dev, test, staging, prod
```

Można też przypisać wyświetlaną nazwę inną niż wartość (format `wyświetlana nazwa : wartość`):
```
Development : dev, Production : prod
```

---

## Interval

Zmienna reprezentująca interwały czasowe. Najczęściej używana do kontrolowania granularności agregacji w zapytaniach.

**Konfiguracja:**
1. **Type** → `Interval`
2. **Values** — predefiniowana lista, np. `1m,10m,30m,1h,6h,12h,1d`
3. **Auto option** — Grafana może automatycznie dobierać interwał na podstawie szerokości wykresu (opcja `Auto`)

**Użycie w PromQL:**
```promql
rate(http_requests_total[${interval}])
```

**Użycie w SQL:**
```sql
$__timeGroupAlias(time_column, $interval)
```

## Constant

Ukryta zmienna ze stałą wartością. Nie wyświetla się w dropdownie dashboardu. Przydatna do przechowywania współdzielonych konfiguracji (np. bazowy URL, prefiks metryki).

**Konfiguracja:**
1. **Type** → `Constant`
2. **Value** — stała wartość

**Przykład — bazowy URL API:**
```
Value: https://api.internal.example.com
```

Użycie w panelu: `$api_base_url/metrics`

Dzięki temu zmiana URL w jednym miejscu (definicji zmiennej) wpływa na wszystkie panele.

---

## Data source

Zmienna pozwalająca użytkownikowi przełączać się między różnymi instancjami tego samego typu źródła danych. Typowe zastosowanie: przełączanie między środowiskiem dev i prod gdy oba używają Prometheus.

**Konfiguracja:**
1. **Type** → `Data source`
2. **Type** (data source) → np. `Prometheus`
3. **Instance name filter** — opcjonalny regex filtrujący wyświetlane instancje, np. `/^prod.*/`

**Użycie w panelu:**
W sekcji **Data source** panelu wybierz zmienną zamiast konkretnej instancji: `$datasource`.

---

## Ad hoc filters

Specjalny typ zmiennej, który dodaje dynamiczne filtry klucz=wartość do wszystkich zapytań używających wybranego źródła danych. Użytkownik sam wybiera klucz i wartość z dropdownów.

**Konfiguracja:**
1. **Type** → `Ad hoc filters`
2. **Data source** → źródło danych, do którego filtry mają być stosowane

Po dodaniu zmiennej na górze dashboardu pojawia się przycisk **+ Add filter**. Użytkownik klika i wybiera np. `environment = prod` — filtr jest automatycznie dołączany do wszystkich zapytań PromQL/Loki na dashboardzie.

> Ad hoc filters działają bez modyfikacji zapytań w panelach. Grafana wstrzykuje filtry automatycznie.

---

## Text box

Prosta zmienna z polem tekstowym. Użytkownik wpisuje dowolny tekst, który jest używany w zapytaniach.

**Konfiguracja:**
1. **Type** → `Text box`
2. **Default value** — opcjonalna wartość domyślna

**Przykład zastosowania — filtrowanie po nazwie:**
```sql
SELECT * FROM logs WHERE message LIKE '%$search_term%'
```

---

## Podsumowanie

| Potrzebujesz... | Użyj typu |
|-----------------|-----------|
| Listy hostów/serwisów z bazy | Query |
| Stałej listy środowisk | Custom |
| Kontroli granularności | Interval |
| Ukrytej stałej konfiguracji | Constant |
| Przełączania między środowiskami | Data source |
| Filtrowania bez edycji zapytań | Ad hoc filters |
| Wyszukiwania po tekście | Text box |
