## Zmienne zależne (chained variables)

Zmienne zależne to zmienne, których lista wartości jest filtrowana na podstawie wartości innej zmiennej. Pozwala to budować hierarchiczne filtry — np. najpierw wybierz środowisko, potem host z tego środowiska.

---

### Przykład: Środowisko → Host → Interfejs

Scenariusz: chcemy dashboardu, gdzie użytkownik wybiera kolejno środowisko → host → interfejs sieciowy.

**Krok 1 — zmienna `env` (Custom)**

| Pole | Wartość |
|------|---------|
| Type | Custom |
| Name | `env` |
| Values | `dev, prod` |

**Krok 2 — zmienna `host` (Query, zależy od `env`)**

| Pole | Wartość |
|------|---------|
| Type | Query |
| Name | `host` |
| Data source | Prometheus |
| Query | `label_values(up{env="$env"}, instance)` |
| Refresh | On dashboard load |

Grafana automatycznie odświeży listę hostów za każdym razem, gdy zmieni się wartość `$env`.

**Krok 3 — zmienna `interface` (Query, zależy od `host`)**

| Pole | Wartość |
|------|---------|
| Type | Query |
| Name | `interface` |
| Data source | Prometheus |
| Query | `label_values(node_network_receive_bytes_total{instance="$host"}, device)` |
| Refresh | On dashboard load |

**Wynik:** Użytkownik widzi trzy dropdowny. Wybór `prod` → lista hostów produkcyjnych → lista interfejsów wybranego hosta.

---

### Przykład z Zabbix: Grupa → Host

**Zmienna `group`:**
```
Query: {zbx_groups}
```

**Zmienna `host` (zależy od `group`):**
```
Query: {zbx_group_hosts: "$group"}
```

---

### Ważna zasada

Zmienne są oceniane od góry do dołu — kolejność na liście w **Settings > Variables** ma znaczenie. Zmienna `host` musi znajdować się poniżej `env`, bo `env` musi mieć wartość, zanim `host` wykona zapytanie.

Kolejność możesz zmieniać przeciągając pozycje na liście zmiennych.

---

## Składnia zmiennych w zapytaniach

Grafana obsługuje trzy notacje. Wszystkie oznaczają to samo, różnią się czytelności i obsługą opcji formatowania.

| Notacja | Przykład | Uwagi |
|---------|---------|-------|
| `$nazwa` | `$host` | Krótka, domyślna |
| `${nazwa}` | `${host}` | Zalecana, gdy zmienna sąsiaduje z tekstem |
| `[[nazwa]]` | `[[host]]` | Stara (deprecated), unikaj |

**Przykład — zmienna wewnątrz tekstu:**
```
node_cpu{instance="${host}:9100"}
```

Bez nawiasów klamrowych `$host:9100` byłoby interpretowane jako zmienna o nazwie `host:9100`.

---

## Modyfikatory formatu (format modifiers)

Kiedy zmienna ma włączoną opcję **Multi-value** lub **Include All**, jej wartość to lista. Różne źródła danych wymagają różnych formatów tej listy. Grafana udostępnia modyfikatory przez składnię `${nazwa:format}`.

| Format | Wynik dla `["web1", "web2", "web3"]` | Zastosowanie |
|--------|---------------------------------------|--------------|
| (brak) | `web1,web2,web3` | Domyślny |
| `csv` | `web1,web2,web3` | CSV |
| `glob` | `{web1,web2,web3}` | Glob (Graphite) |
| `regex` | `web1\|web2\|web3` | Wyrażenie regularne (PromQL) |
| `pipe` | `web1\|web2\|web3` | Jak regex |
| `json` | `["web1","web2","web3"]` | JSON |
| `lucene` | `("web1" OR "web2" OR "web3")` | Elasticsearch |
| `percentencode` | `web1%2Cweb2%2Cweb3` | URL encoding |
| `singlequote` | `'web1','web2','web3'` | SQL |
| `doubleqoute` | `"web1","web2","web3"` | SQL |
| `sqlstring` | `'web1','web2','web3'` | SQL IN clause |

### Praktyczne przykłady

**PromQL — multi-value działa z `regex`:**
```promql
rate(http_requests_total{instance=~"${host:regex}"}[5m])
```
Generuje: `instance=~"web1|web2|web3"`

**SQL — multi-value w klauzuli IN:**
```sql
SELECT * FROM metrics WHERE host IN (${host:sqlstring})
```
Generuje: `host IN ('web1','web2','web3')`

**Elasticsearch:**
```
host:(${host:lucene})
```
Generuje: `host:("web1" OR "web2" OR "web3")`

## Zmienne w tytułach i opisach paneli

Zmienne działają nie tylko w zapytaniach. Możesz ich używać w:
- **Tytule panelu**: `CPU usage — $host`
- **Opisie panelu**: `Dane dla środowiska $env, host $host`
- **Linku panelu (Data link)**: `https://monitoring.internal/$host/details`
- **Tytule osi**
- **Thresholdach** — tylko wartości liczbowe

---

## Podsumowanie

- Zmienne zależne budują hierarchiczne filtry — zmień wartość zmiennej nadrzędnej, a lista podrzędnej odświeży się automatycznie.
- Używaj `${nazwa}` zamiast `$nazwa` gdy zmienna sąsiaduje z innymi znakami.
- Przy multi-value zawsze dobierz właściwy modyfikator formatu: `regex` dla PromQL, `sqlstring` dla SQL, `lucene` dla Elasticsearch.
