# Tworzenie dashboardów
![Prometheus](/grafiki/m5-7.2-tworzenie-dashboardow.png)
Dashboard w Grafanie to skonteneryzowany zestaw paneli, zmiennych i ustawień zapisany jako struktura JSON. Skuteczne budowanie dashboardów wymaga zrozumienia zarówno mechaniki tworzenia poszczególnych paneli, jak i technik czyniących dashboard uniwersalnym i skalowalnym — przede wszystkim zmiennych szablonowych oraz organizacji w wiersze.

## Proces budowy dashboardu krok po kroku

1. **Utworzenie nowego dashboardu** — w menu **Dashboards → New → New Dashboard**. Grafana tworzy pusty dashboard gotowy do dodawania paneli.
2. **Dodanie panelu** — przycisk **Add → Visualization**. Wymaga wyboru źródła danych (data source) oraz zdefiniowania zapytania PromQL w edytorze zapytań.
3. **Konfiguracja wizualizacji** — wybór typu panelu (Time series, Stat, Gauge, Table itd.) w prawym panelu bocznym, dostosowanie osi, jednostek (Unit), progów kolorystycznych (Thresholds) oraz opisu (Panel options → Title, Description).
4. **Ustawienie zakresu odświeżania i przedziału czasowego** — w prawym górnym rogu dashboardu konfiguruje się domyślny **Time range** (np. Last 6 hours) oraz **Refresh interval** (np. 30s), które mogą być nadpisywane przez użytkownika podczas przeglądania.
5. **Zapisanie dashboardu** — z nadaniem nazwy, przypisaniem do folderu oraz (opcjonalnie) tagów ułatwiających wyszukiwanie.
6. **Iteracyjne dodawanie kolejnych paneli** i porządkowanie układu metodą przeciągnij-i-upuść (drag & drop), z regulacją rozmiaru paneli na siatce.

## Zmienne dashboardu (template variables)

Zmienne pozwalają zbudować jeden uniwersalny dashboard, który użytkownik parametryzuje w czasie przeglądania, zamiast tworzyć osobny dashboard dla każdego hosta, zadania czy środowiska. Definiuje się je w **Dashboard settings → Variables → New variable**.

Najczęściej stosowany typ to **Query**, w którym wartości zmiennej pochodzą bezpośrednio z Prometheusa poprzez funkcję `label_values()`:

```
label_values(up, job)
```

Powyższe zapytanie tworzy zmienną `$job`, której lista wartości to wszystkie unikalne wartości etykiety `job` występujące w metryce `up`. Analogicznie buduje się zmienną zależną od wcześniej wybranej:

```
label_values(up{job="$job"}, instance)
```

Zmienna `$instance` filtruje się wtedy tylko do instancji należących do wybranego wcześniej `$job` — to przykład **zmiennej zależnej (chained variable)**, gdzie zmiana `$job` automatycznie odświeża listę dostępnych wartości `$instance`.

Zdefiniowane zmienne wykorzystuje się bezpośrednio w zapytaniach paneli:

```promql
node_cpu_seconds_total{job="$job", instance="$instance", mode!="idle"}
```

Kluczowe opcje konfiguracyjne zmiennej:

- **Multi-value** — pozwala zaznaczyć wiele wartości jednocześnie (np. kilka instancji naraz); w zapytaniu PromQL wymaga wtedy użycia operatora regex zamiast równości, co Grafana realizuje automatycznie poprzez funkcję `{{ $job }}` przekształcaną do formy `job=~"$job"` przy multi-select.
- **Include All option** — dodaje wartość specjalną „All”, reprezentowaną w zapytaniu jako wyrażenie regex dopasowujące wszystkie wartości.
- **Refresh** — moment odświeżania listy wartości: „On Dashboard Load” lub „On Time Range Change” (istotne, gdy zestaw dostępnych etykiet zmienia się wraz z zakresem czasu, np. przy skalowaniu instancji).
- **Sort** — sortowanie alfabetyczne lub numeryczne listy wartości, poprawiające czytelność selektora.

Przykład definicji zmiennych w eksportowanym JSON dashboardu:

```json
{
  "templating": {
    "list": [
      {
        "name": "job",
        "type": "query",
        "datasource": "Prometheus-prod",
        "query": "label_values(up, job)",
        "refresh": 2,
        "sort": 1
      },
      {
        "name": "instance",
        "type": "query",
        "datasource": "Prometheus-prod",
        "query": "label_values(up{job=\"$job\"}, instance)",
        "refresh": 2,
        "sort": 1,
        "multi": true,
        "includeAll": true
      }
    ]
  }
}
```

## Organizacja paneli w wiersze (rows)

Przy dashboardach zawierających kilkanaście lub więcej paneli kluczowe jest grupowanie ich w **rows** — logiczne sekcje, które można zwijać (collapse) i rozwijać. Rząd dodaje się poleceniem **Add → Row**, po czym przeciąga się do niego panele tematycznie powiązane, np.:

- Row „Zasoby systemowe” — CPU, RAM, dysk, sieć.
- Row „Metryki aplikacji” — czas odpowiedzi, liczba żądań, kody błędów HTTP.
- Row „Baza danych” — połączenia, zapytania na sekundę, opóźnienia replikacji.

Zwinięte wiersze (**collapsed rows**) poprawiają czytelność dashboardu na pierwszy rzut oka, pozwalając użytkownikowi rozwijać tylko interesujące go sekcje. Dobrą praktyką jest umieszczanie najważniejszych wskaźników (np. kluczowe SLO) w pierwszym, zawsze rozwiniętym wierszu na górze dashboardu.

## Linkowanie dashboardów

Grafana pozwala tworzyć powiązania nawigacyjne między dashboardami na dwóch poziomach:

- **Dashboard links** (Dashboard settings → Links) — linki widoczne w nagłówku całego dashboardu, prowadzące np. z dashboardu przeglądowego klastra do szczegółowego dashboardu konkretnego węzła, z zachowaniem bieżącego zakresu czasu i wartości zmiennych (opcja **Keep time range** i **Include variable values**).
- **Panel links / Data links** (na poziomie pojedynczego panelu lub serii danych) — pozwalają np. kliknąć w słupek na wykresie i przejść bezpośrednio do dashboardu ze szczegółami dla danej wartości etykiety, przekazując ją jako parametr URL (`var-instance=${__field.labels.instance}`).

Takie linkowanie pozwala budować hierarchię dashboardów typu drill-down: ogólny przegląd klastra → przegląd węzła → szczegóły procesu, bez konieczności ręcznego przełączania zmiennych za każdym razem.

## Import gotowych dashboardów z grafana.com

Społeczność Grafany publikuje w katalogu **grafana.com/grafana/dashboards** gotowe dashboardy dla popularnych eksporterów, identyfikowane numerycznym ID. Import wykonuje się przez **Dashboards → New → Import**, wpisując ID dashboardu, np.:

- **1860** — „Node Exporter Full”, kompleksowy dashboard metryk systemowych z `node_exporter` (CPU, pamięć, dyski, sieć, temperatura).
- **3662** — „Prometheus 2.0 Overview”, metryki samego serwera Prometheus.
- **7362** — dashboard dla `mysqld_exporter`.

Po wpisaniu ID Grafana pobiera definicję JSON i wymaga wskazania, które źródło danych z lokalnej instancji ma zostać podstawione pod placeholder zdefiniowany w oryginalnym dashboardzie (zwykle zmienna `DS_PROMETHEUS`). Zaimportowany dashboard warto następnie:

- Przenieść do właściwego folderu.
- Zweryfikować zgodność nazw etykiet z lokalną konfiguracją `node_exporter` (starsze dashboardy mogą odwoływać się do etykiet lub metryk usuniętych w nowszych wersjach eksportera, np. zmiany w nazewnictwie metryk dyskowych).
- Dostosować progi (thresholds) do realiów własnej infrastruktury zamiast pozostawiać wartości domyślne autora dashboardu.

Import gotowych dashboardów jest efektywnym punktem startowym, ale nie zwalnia z konieczności ich przeglądu i dostosowania — dashboardy tworzone przez społeczność bywają nadmiarowo rozbudowane lub oparte na nieaktualnych wersjach eksporterów.
