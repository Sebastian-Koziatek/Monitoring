# Typy danych: instant vectors, range vectors, scalars, strings

![Prometheus](/grafiki/m5-5.1-typy-danych.png)

PromQL (Prometheus Query Language) operuje na czterech ściśle zdefiniowanych typach danych. Zrozumienie, jaki typ zwraca dane wyrażenie, jest kluczowe — wiele funkcji i operatorów akceptuje tylko konkretny typ wejściowy, a błędy typu są jedną z najczęstszych przyczyn nieudanych zapytań. Każde wyrażenie PromQL da się jednoznacznie zaklasyfikować do jednego z poniższych typów.

## 1. Instant vector (wektor chwilowy)

Instant vector to zbiór szeregów czasowych, z których każdy zawiera dokładnie jedną próbkę (wartość) dla danego momentu w czasie (tzw. evaluation time). Jest to najczęściej używany typ danych — bezpośrednie odwołanie się do nazwy metryki zwraca właśnie instant vector.

```promql
http_requests_total
```

To zapytanie zwraca wszystkie szeregi czasowe o nazwie `http_requests_total`, każdy z pojedynczą, najświeższą wartością (nie starszą niż limit `lookback delta`, domyślnie 5 minut) oraz pełnym zestawem etykiet.

Przykładowy wynik:

```
http_requests_total{instance="10.0.0.1:9100", job="node", method="GET", status="200"}  1234
http_requests_total{instance="10.0.0.1:9100", job="node", method="POST", status="500"}  17
```

Instant vector jest wynikiem m.in.:
- bezpośredniego selektora metryki,
- operatorów arytmetycznych i logicznych między wektorami (`+`, `-`, `and`, `or`, `unless`),
- funkcji agregujących (`sum()`, `avg()`, `max()`, `count()` itd.),
- funkcji przyjmujących instant vector i zwracających instant vector (np. `abs()`, `round()`, `clamp_max()`).

## 2. Range vector (wektor zakresowy)

Range vector to zbiór szeregów czasowych zawierających wiele próbek w zadanym przedziale czasu wstecz od punktu ewaluacji. Range vector powstaje przez dodanie do selektora metryki nawiasu kwadratowego z długością zakresu (tzw. duration).

```promql
http_requests_total[5m]
```

To zapytanie zwraca dla każdego szeregu `http_requests_total` wszystkie surowe próbki zebrane w ciągu ostatnich 5 minut, wraz z ich znacznikami czasu.

Jednostki czasu akceptowane w duration: `ms`, `s`, `m`, `h`, `d`, `w`, `y` — można je łączyć, np. `1h30m`.

**Ważne:** range vector nie może być bezpośrednio renderowany na wykresie ani zwracany jako wynik zapytania w Grafanie/API — jest to typ wyłącznie pośredni, który trzeba przetworzyć funkcją redukującą go do instant vector, np.:

```promql
rate(http_requests_total[5m])
avg_over_time(node_load1[10m])
increase(http_requests_total[1h])
```

Range vector jest jedynym poprawnym argumentem dla funkcji z rodziny `_over_time` (`sum_over_time`, `max_over_time`, `min_over_time`, `avg_over_time`, `stddev_over_time`) oraz dla `rate()`, `irate()`, `increase()`, `delta()`, `deriv()`, `predict_linear()`, `resets()`, `changes()`.

## 3. Scalar (skalar)

Scalar to pojedyncza liczba zmiennoprzecinkowa, bez etykiet i bez przypisania do konkretnego szeregu czasowego. Skalar powstaje m.in. jako:
- literał liczbowy wpisany wprost w zapytaniu (`5`, `0.95`, `3.14`),
- wynik funkcji `scalar()`, która konwertuje jednoelementowy instant vector do skalara,
- wynik niektórych funkcji agregujących zastosowanych bez etykiet, gdy PromQL "spłaszcza" wynik.

```promql
count(up)
```

Uwaga: `count(up)` technicznie zwraca instant vector z jednym elementem (bez etykiet, chyba że użyto `by(...)`) — nie jest to skalar sensu stricto, dopóki nie użyjemy funkcji `scalar()`:

```promql
scalar(count(up))
```

Przykład czystego skalara:

```promql
42
```

Skalary są szczególnie użyteczne w operacjach arytmetycznych z wektorami — pozwalają np. przeskalować wszystkie wartości wektora o stałą liczbę:

```promql
node_memory_MemTotal_bytes / 1024 / 1024
```

Tutaj `1024` to skalar, a wynik dzielenia instant vector przez skalar pozostaje instant vector (etykiety są zachowane).

## 4. String (łańcuch znaków)

String to typ danych zarezerwowany obecnie głównie do użytku wewnętrznego i przyszłej rozbudowy języka — w praktyce produkcyjnej PromQL rzadko operuje bezpośrednio na stringach jako wyniku końcowym. Literały łańcuchowe zapisuje się w cudzysłowach lub apostrofach:

```promql
"to jest string"
'to również string'
```

String pojawia się głównie jako:
- wartość etykiety w selektorze (`{job="node_exporter"}`),
- argument funkcji, np. `label_replace()` czy `label_join()`, które operują na wartościach etykiet jako stringach.

```promql
label_replace(up, "hostname", "$1", "instance", "(.*):.*")
```

## Selektory etykiet

Selektor metryki można filtrować po etykietach za pomocą czterech operatorów dopasowania:

| Operator | Znaczenie | Przykład |
|---|---|---|
| `=` | dokładne dopasowanie wartości | `up{job="node"}` |
| `!=` | wykluczenie dokładnej wartości | `up{job!="node"}` |
| `=~` | dopasowanie wyrażeniem regularnym (RE2) | `up{job=~"node.*"}` |
| `!~` | wykluczenie wyrażeniem regularnym | `up{job!~"node.*"}` |

Selektory można łączyć — wszystkie warunki muszą być spełnione jednocześnie (logiczne AND):

```promql
http_requests_total{job="api", status=~"5..", method!="OPTIONS"}
```

Wyrażenia regularne w PromQL są zawsze zakotwiczone (implicit `^...$`), więc `job=~"node"` dopasuje tylko dokładnie `node`, a nie np. `node_exporter` — do tego potrzebne jest `job=~"node.*"`.

## Modyfikatory czasowe: offset oraz @

**`offset`** pozwala odwołać się do danych sprzed określonego czasu względem punktu ewaluacji zapytania:

```promql
http_requests_total offset 1h
rate(http_requests_total[5m] offset 1d)
```

Pierwsze zapytanie zwraca wartość `http_requests_total` sprzed godziny; drugie liczy `rate()` na podstawie danych z okna 5-minutowego sprzed jednego dnia — przydatne do porównań dzień-do-dnia lub tydzień-do-tygodnia.

**`@`** (modyfikator znacznika czasu) pozwala związać zapytanie z konkretnym, stałym punktem w czasie (timestamp Unix), niezależnie od czasu ewaluacji zapytania:

```promql
http_requests_total @ 1700000000
rate(http_requests_total[5m] @ 1700000000)
```

Można też użyć specjalnych wartości `start()` i `end()` w kontekście zapytań zakresowych (range queries) w API:

```promql
rate(http_requests_total[5m] @ end())
```

`offset` i `@` można łączyć w jednym wyrażeniu; kolejność zapisu nie ma znaczenia semantycznego, ale konwencjonalnie zapisuje się `[5m] @ 1700000000 offset 1m`.

## Podsumowanie zależności typów

| Typ wejścia | Typowa operacja | Typ wyniku |
|---|---|---|
| instant vector | selektor `metric{...}` | instant vector |
| instant vector + `[5m]` | zakres czasowy | range vector |
| range vector | `rate()`, `increase()`, `avg_over_time()` | instant vector |
| instant vector | `sum()`, `avg()`, `count()` | instant vector (zredukowany) |
| instant vector (1 element) | `scalar()` | scalar |
| instant vector, scalar | operator arytmetyczny | instant vector |

Znajomość tej tabeli pozwala uniknąć najczęstszego błędu początkujących: próby użycia funkcji `rate()` bezpośrednio na instant vector bez nawiasu zakresowego, co Prometheus odrzuci z błędem parsowania.
